# Comprehensive Rules

- `MagicCompRules.txt` — the official text, fetched by the Reference data workflow from the URL in `SOURCE.txt`. To move to a new CR release, change that URL.
- `rules.json` — the parsed rules (rule number → text, examples, parent/children) plus the glossary.
- `TRACE.md` — which rules the engine implements and tests. Generated by `pnpm rules:trace`; don't edit by hand.

## Citing rules in code

- Write `CR 117.3a` next to the code that implements that rule, one number per `CR`.
- Name tests after the rule they check: `it('CR 704.5a: a player at 0 life loses', …)`. The CR's own "Example:" paragraphs make good test cases.
- Mention rules that aren't implemented yet as `rule 613` (no `CR`), so the trace stays honest.
- `pnpm rules:check` (run in CI) fails if a citation names a rule that doesn't exist. This is how renumbering in a new CR release gets caught.
